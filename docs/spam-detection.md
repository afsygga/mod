# Детект спама

Ядро — [`spam-engine/SpamEngine.ts`](../backend/src/spam-engine/SpamEngine.ts).
**Чистая логика без БД и сети** ([§14](../AGENTS.md)):

```
analyze(username, message, suspicion?) → { score, reasons, similarityPct,
                                           whitelistedFlood?, suspicionBonus? }
```

Профиль на юзера с историей (обрезается по времени и до 50 записей); деривативы
(нормализация/агрегаты/счётчики) считаются один раз при вставке — иначе флуд
делал бы `analyze()` O(n²). Idle-профили подметаются раз в 5 мин.

## Модель скоринга (0–100)

| Проверка | Макс. очков |
|---|---|
| Точный дубликат сообщения | +40 |
| Cosine-похожесть на недавние | +30 |
| Промо-намерение (channel/subscribe и т.п.) | +25 |
| Burst (слишком много сообщений в окне) | +20 |
| Ссылка (http/www) | +15 |
| Повтор структуры предложения | +15 |

Плюс правила: эмоут/эмодзи-флуд, ротация `A→B→A`, anti-evasion (leet-спик,
latin→cyrillic). `triggerAfterN` (per-channel) не даёт реагировать до N повторов.
**Хард-флуд (3+ сообщения за 10с)** обходит и гейт `triggerAfterN`, и whitelist,
но whitelist-флуд помечается `whitelistedFlood` → уходит в очередь **без**
автомута (тройные эмоут-хайпы — частое легитимное поведение).

## Пороги

Живут в `settings`, редактируются из панели без рестарта:

| Диапазон | Действие |
|---|---|
| 0–69 | норма |
| 70–89 | очередь модерации (`detectThreshold`) |
| 90–100 | автомут (`autoMuteThreshold`) |

Одно терминальное решение на сообщение: `clean` / `queued` / `automod` /
`whitelist_suppressed` / `role_ignored` — считается в метрике
`afsyg_spam_decisions_total`.

## Сигнал подозрительности (внешний)

Метки Twitch (обход бана, забанен в связанных каналах и т.п.) приходят через
EventSub и **модифицируют**, а не триггерят score ([§20](../AGENTS.md)):

- Добавляется только к **уже ненулевому** score — подозрительный юзер, пишущий
  нормально, в очередь не попадает (иначе это теневой бан).
- **Максимум признаков, а не сумма** (признаки сильно коррелируют).
- Очки настраиваются (`suspicion_points_*`), дефолты: restricted 18,
  ban_evader 18, banned_in_shared 15, active_monitoring 10.
- **Свойство безопасности:** очки (макс. 18) меньше разрыва между порогами (70→90
  = 20). Худший случай `69 + 18 = 87` остаётся ниже автомута — метка доводит до
  очереди, решение принимает человек. **Ломается, если сузить пороги или поднять
  `suspicion_points_*`.**

## Как менять/тестировать

Тест-раннера нет — сценарные `tsx`-скрипты в скретчпаде, мокающие `db`/`fetch`
([§11](../AGENTS.md)). Для чистой логики (SpamEngine) гоняй сценарии; перед пушем
обязательно `npx tsc --noEmit` + `npm run build`.

## Известный пробел: рейды

`analyze()` смотрит историю **одного** юзера. Скоординированный рейд (много свежих
аккаунтов, одно сообщение на каждого) кросс-юзерно **не ловится** —
см. [`AGENTS.md` §23](../AGENTS.md). Одиночный спамер и флуд детектятся штатно.
