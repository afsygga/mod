# Эксплуатация

Операторский справочник: переменные окружения, деплой, фоновые джобы и
диагностика. Инварианты токенов и полные runbook'и — в
[`AGENTS.md` §5–§12](../AGENTS.md).

## Переменные окружения

Живут в `.env` **на хосте рядом с `docker-compose.yml`** (не в репо, не едут из
CI). Полная таблица с назначением — [`AGENTS.md` §6](../AGENTS.md). Критичный
минимум:

| Переменная | Без неё |
|---|---|
| `TWITCH_CLIENT_ID` / `TWITCH_CLIENT_SECRET` | Ломается всё, что касается Twitch (OAuth, рефреш, EventSub, стримы) |
| `TWITCH_BOT_USERNAME` / `TWITCH_BOT_OAUTH` | Нет глобального IRC-бота (статичный токен, без refresh) |
| `GOOGLE_CLIENT_ID` | Нет входа на сайт |
| `ADMIN_EMAIL` | Первый вход не получит admin |
| `JWT_SECRET` | Нет подписи сессий и OAuth `state` |
| `DATABASE_URL` (+ `POSTGRES_*`) | Нет БД |
| `STEAM_API_KEY` | Steam-синхронизация спит (остальное работает) |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | Нет Telegram-уведомлений (опционально) |

### Настройка ретенции сообщений (новое)

| Переменная | Дефолт | Смысл |
|---|---|---|
| `MESSAGE_RETENTION_DAYS` | `30` | Хранить сообщения N дней. `<= 0` — джоба отключена целиком |
| `MESSAGE_RETENTION_KEEP_SCORE` | `70` | Сообщения со `spam_score >=` этого **не удаляются** никогда (история для расследований) |

Дефолт `70` совпадает с порогом детекта — то есть всё, что попадало в очередь или
автомут, сохраняется, а обычный чат старше 30 дней вычищается. См.
[«Фоновые джобы»](#фоновые-джобы) ниже.

## Деплой

**Триггер — `push` в `main`** (стандартно можно без спроса, память
`always-push-to-main`; силовые операции — нет). Дальше автоматически:

1. GitHub Actions собирает **оба** образа (backend + frontend) и пушит в ghcr.io.
2. **Watchtower** на хосте подтягивает новые образы и пересоздаёт контейнеры
   (обычно 1–3 мин после успешной сборки).

После пуша:

- Дождаться `conclusion: success` в Actions, затем Watchtower.
- **Менял фронт → бампни [`frontend/VERSION`](../frontend/VERSION)** (иначе не
  отличить, докатился ли деплой).
- Проверка версии фронта в проде:

  ```bash
  curl -s https://afsyg.gay/$(curl -s https://afsyg.gay/ | grep -o 'assets/index-[^"]*\.js') | grep -o '"2\.[0-9]*"'
  ```

Подробности CI/Watchtower/env-запекания — [`AGENTS.md` §5](../AGENTS.md).

## Фоновые джобы

Все инструментированы метрикой `afsyg_background_job_*{job}` ([§17](../AGENTS.md)):

| Джоба (`job`) | Период | Что делает |
|---|---|---|
| стрим-поллер | 60с | Старт/энд сессий, пик зрителей, смены категории |
| `steam_sync` | 60с | Steam-присутствие → категория Twitch ([§22](../AGENTS.md)) |
| токен-валидатор | 1ч | Валидация всех OAuth-сессий, реактивный рефреш ([§8](../AGENTS.md)) |
| `message_retention` | 6ч | Чистка старых сообщений батчами по 5000 (первый запуск — через 2 мин после старта) |

Метрики джоб: `afsyg_background_job_last_success_timestamp_seconds{job}`,
`..._last_duration_seconds{job}`, `..._in_progress{job}`,
`afsyg_background_job_runs_total{job,result}`.

## Уведомления

Telegram-пинги о попадании в очередь — [`telegram/TelegramBot.ts`](../backend/src/telegram/TelegramBot.ts):

- **Батч на chat_id**: события копятся 3с и уходят одним сообщением (одиночное —
  с кнопками mute/ban/skip; несколько — сводкой «spam wave»).
- **Per-user кулдаун (новое)**: повторные срабатывания по **тому же** юзеру в
  окне `NOTIFY_COOLDOWN_MS` (60с) не создают новый пинг. Раньше при флуде одного
  спамера прилетал пинг на **каждое** его сообщение над порогом. Кулдаун гасит
  только Telegram — WS-`queue_add` для дашборда остаётся живым, чтобы растущий
  score продолжал обновлять открытую панель.

## Безопасность и сессии

**Сессии пользователей.** Каждый вход создаёт запись в `sessions` (TTL 30 дней,
Bearer-токен в localStorage). Пользователь видит свои активные сессии и может
отозвать любую на сайте: **Настройки → вкладка «Сессии»**. Отзыв удаляет строку в
`sessions` — токен перестаёт работать при следующем запросе (`authenticate` его
не найдёт). Токены сессий наружу не отдаются: список оперирует публичным id =
префикс `sha256(token)`.

**Ротация статичного бот-токена (`TWITCH_BOT_OAUTH`).** Это единственный
Twitch-токен без refresh (§7) и явный SPOF — при протухании глобальный IRC-бот
не самолечится. Ротация — **ручная операция на хосте**, не действие на сайте
(ввод токенов в веб-форму запрещён политикой):

1. Под аккаунтом бота сгенерировать новый OAuth-токен (нужен `chat:read` +
   `chat:edit`; напр. через https://twitchapps.com/tmi/ или свой OAuth-флоу).
2. На хосте в `.env` рядом с `docker-compose.yml` обновить `TWITCH_BOT_OAUTH`
   (и `TWITCH_BOT_USERNAME`, если сменился аккаунт).
3. Пересоздать контейнер с сохранением env:
   ```bash
   docker compose up -d --force-recreate backend
   ```
4. Проверить в логах `Global IRC connected` и что сообщения снова идут
   (вкладка «Здоровье» → бот зелёный). Симптом протухания — `Global IRC auth
   failed ... regenerate` (см. диагностику ниже и память `irc-token-expiry-ingestion-death`).

## Диагностика поломок (кратко)

Полные runbook'и — [`AGENTS.md` §12](../AGENTS.md). Быстрые маркеры:

| Симптом | Куда смотреть |
|---|---|
| Дашборд открыт, но сообщений/детекта нет | Мёртвое IRC-поступление. `curl https://afsyg.gay/health` (200 = веб ок) → логи бэкенда → `Global IRC auth failed` = перегенерировать `TWITCH_BOT_OAUTH`. Память `irc-token-expiry-ingestion-death` |
| `TWITCH_CLIENT_ID not set` / пусто в аналитике | В контейнере нет env: `docker exec twitchmod_backend printenv \| grep TWITCH`; починить `.env` + `docker compose up -d --force-recreate backend` |
| Белый экран после деплоя фронта | Кэш `index.html` (уже исправлено в `nginx.conf`: `no-cache` на html, `immutable` на `/assets/`) |
| «Задеплоил, а поведения нет» | Один образ докатился, другой нет. Проверить, что Watchtower пересоздал **оба** |
| `Slow query … messages …` | Хвост роста таблицы — теперь закрывается джобой `message_retention` (см. выше) |
| Действия модера канала не в логах | EventSub без скоупа: реальный модер канала должен перезайти через Twitch ([§12](../AGENTS.md), вкладка «Здоровье») |
